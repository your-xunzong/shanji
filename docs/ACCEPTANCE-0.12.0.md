# 0.12.0 签名更新与中文字体验收

> v0.12.0 是首个内置更新公钥的版本，需要先手动安装。它能发现并安装后续稳定版，不能用同版本 Release 完成全流程验收。测试前先备份事项数据，并确认“关于闪记”显示 0.12.0。

## 1. 默认离线与授权

1. 首次启动或从旧版本升级后，主工作台显示“获取新版本提醒”，说明每天最多连接 GitHub 一次且不上传事项、备注或本地路径。
2. 点击“保持离线”后授权条消失；重新打开应用不会自动检查，设置页仍可手动检查或重新启用。
3. 点击“启用并检查”后立即检查一次；之后自动检查每天最多一次，快速录入、保存和提醒不等待网络。
4. 断网、超时或 GitHub 不可用时，自动检查保持安静；手动检查显示可重试提示，当前程序和事项数据不改变。

## 2. 更新发现与说明

1. 在 GitHub 发布高于 0.12.0 的稳定 Release，并确保包含流水线生成的 `latest.json`、对应平台更新包和 `.sig`；草稿或预发布不得被客户端发现。
2. 从设置页“立即检查更新”或托盘“检查更新”触发后，应显示目标版本、发布日期和 3–6 条中文说明；主工作台与托盘提示保持一致。
3. 点击“24 小时后提醒”，该版本当天不再主动提示，手动检查仍可重新打开。
4. 同一版本只发送一次系统更新通知。升级完成后的首次启动显示一次本版更新说明，再次启动不重复；“关于闪记 → 查看本版更新说明”始终可主动查看。

## 3. 下载、签名与恢复

1. Windows NSIS 安装版点击“下载更新”，检查真实字节或百分比进度；取消后仍能正常使用当前版本，重新打开可再次下载。
2. 下载完成后点击“安装并重启”；闪记关闭、被动安装并重新启动，版本号更新，原事项、设置、提醒历史和草稿保持不变。
3. 分别用错误仓库 URL、被篡改更新包和错误签名做隔离测试；三种情况都必须拒绝安装，不提供“仍然安装”，并允许重试或打开官方发布页。
4. 安装失败或重启失败时，错误文案说明当前数据安全且可重试；不得显示内部命令、数据库字段、堆栈或事项正文。

## 4. 便携版与三平台降级

- Windows 便携版只提示版本并打开该版本的官方 Release 下载页，不自动覆盖 `shanji.exe` 或便携数据目录。
- Linux AppImage 验证签名更新；DEB/包管理器安装只打开官方下载页。macOS 验证应用签名、公证、安装与重启恢复。
- 未完成相应实机验证的平台保持“待验证”，不得仅凭 CI 构建标记正式支持。

## 5. 字体、键盘与状态界面

- 用真实中文事项检查主工作台、快速录入、设置、甘特图、邮件、仓库、提醒中心和更新抽屉：正文整体增大，中文标题不再使用 Bahnschrift，按钮/输入清楚且无截断。
- 在 760×560、浅色、深色、高对比度、强制颜色和减少动态效果下检查授权条、空状态、检查中、无更新、有更新、下载、取消、失败和安装状态。
- 更新抽屉打开后焦点落在关闭按钮，Tab 不离开抽屉；Escape 在安全阶段关闭并把焦点还给来源按钮，下载或安装阶段不会被误关。中文输入法组合态不触发提交或关闭。
