# 0.13.3 提醒、恢复、小结与仓库去重验收

> 本清单用于安装包和真实数据副本验收。开始前先备份数据；Word 与仓库步骤使用测试副本，不直接处理唯一文件。

## A. 默认提醒与单条覆盖

1. 在“后台设置”把普通事件默认改为“强制”，把重要事项默认改为“强调”。
2. 打开一个未设置事件类型的事项，切换为“普通”：提醒方案应自动变为“强制”，来源显示“跟随‘普通’默认”。
3. 把该事项单独改为“重复”并保存：重新打开后仍为“重复”，来源显示为单条设置。
4. 点击“恢复默认”：方案应回到当前普通默认“强制”。
5. 勾选“标记为重要”：方案应切换为重要默认“强调”；取消重要后重新匹配普通默认。
6. 修改后台默认值后，未再次编辑的既有事项不应被静默批量改写。

## B. 已完成恢复

1. 完成一个未来到期的重复事项，在“已完成”中点击“恢复为未完成”。
2. 原标题、备注、事件类型、类型、标签和重要标记应保留，事项回到待处理；下一次提醒只落在未来。
3. 对已过期的一次性事项执行恢复：事项应恢复，但不得立即补发旧通知；界面提示调整提醒时间。
4. 模拟保存失败时，事项应保持已完成，并提供可重试提示。

## C. Word 月度与季度小结

1. 在模板正文放置 `{{period_label}}`、`{{total_count}}` 等单值占位符。
2. 在 Word 表格的一整行内放置同一集合的占位符，例如 `{{completed_item.title}}`、`{{completed_item.completed_at}}`；该行将作为重复模板行。
3. 在“导出与小结”选择月度或季度、模板和输出位置。生成后模板原文件不变；输出保留字体、边框、底色和页面设置，且不含未替换占位符。
4. 分别验证空集合、多条长标题、中文、XML 特殊字符、月末和季度边界。
5. 将集合占位符放到表格外、同一表格行混用两个集合或输入未知占位符时，应在生成前得到可行动提示，既有输出不得被覆盖。

## D. 个人仓库去重

1. 使用数据副本制造仅元数据不同但业务内容相同的冲突：预览应计为“完全重复”，整理后只保留一个活跃事项，不再重复提醒。
2. 制造标题、备注、状态、时间、事件类型、类型或标签不同的冲突：界面应列出差异，不得自动覆盖。
3. 分别验证“保留本机”“保留仓库”“两份都保留”；处理前有备份，未保留副本可从回收站或审计记录追溯。
4. 再次同步同一数据包不得重建同一冲突；在另一设备修改业务字段后应产生新的真实冲突。

## E. 重复提醒完整通知

1. 关闭开关时，重复提醒外观与旧版一致。
2. 开启“重复提醒显示完整信息”，重复方案通知应包含事件类型、类型、标签和下一次提醒，不包含备注。
3. 强调、一次性、强制和自定义通知不得因此改变内容或频率。
4. Windows、macOS、Linux 分别记录系统通知中心的折叠或截断情况；若详情不可见，正文点击与既有操作仍必须可用。

## F. 开机启动

1. 在 Windows 启用开机启动并保存，确认 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 中出现闪记启动项；注销并重新登录后，闪记以后台模式启动。
2. 保留数据库中的启用偏好但手动移除测试环境的系统启动项，再次勾选并保存：启动项必须重建，不得只显示“设置已保存”。
3. 关闭开机启动并保存：启动项应移除；模拟系统拒绝写入时，界面应说明没有保存，数据库偏好和系统状态保持原样。

## G. 发布门槛

- 从 schema 11 的数据副本升级，确认自动备份、schema 12、旧事项“旧数据保留”和失败恢复。
- 运行 `pnpm check`、`pnpm test`、`pnpm build`、`pnpm version:check`、`pnpm installer:check`，以及 Rust 格式、Clippy 和测试。
- Windows 安装版、Windows 便携版、macOS、Linux 至少各完成一次启动、保存、恢复、提醒与小结生成。
- 只有安装包、签名、SHA-256、远端标签与 GitHub Release 只读校验全部通过后，才把 `Unreleased` 内容归档为正式 v0.13.3 发布记录。
