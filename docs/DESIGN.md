# 闪记界面设计基线

> 设计流程：新增页面或重构界面必须先使用 `frontend-design` skill 完成“构思—自检—实现—截图复核”两轮设计。未形成具体用户、页面唯一任务、视觉 token、布局草图和标志性元素前，不进入 UI 代码实现。

## 设计命题

闪记面向频繁切换上下文的桌面工作者。界面的单一任务是让用户看清“现在记什么、什么时候再出现”，而不是呈现一个缩小版项目管理系统。

## 视觉系统

### 色彩

- 工作台 `#E9EDF2`：应用背景，降低长时间使用的眩光。
- 纸白 `#F9FAFB`：输入和事项内容。
- 墨色 `#17202A`：主要文字。
- 雾蓝 `#7D91A6`：普通时间轨和次要信息。
- 松针 `#2F6F62`：完成、保存成功。
- 朱砂 `#D94B35`：只用于“今日必做”、严重逾期和破坏性动作。

### 字体

- 标题：`Bahnschrift` / `PingFang SC` / `Microsoft YaHei`，稍窄字宽，表达桌面工具的精确感。
- 正文：系统中文无衬线字体，避免下载字体和增加安装体积。
- 时间与数据：`Cascadia Mono` / `SFMono-Regular` / 等宽回退，便于快速扫描。

### 布局

管理页采用窄导航、主事项流和可选详情抽屉。快速录入窗只有输入、时间、分类、今日必做和提交反馈。

```text
管理页                           快速录入
┌──────┬──────────────────┐    ┌────────────────────┐
│ 筛选 │ 日期与新增        │    │ 写下要记的事…      │
│      ├──────────────────┤    │                    │
│ 分类 │ ┃ 时间轨 事项     │    │ 时间 分类 今日必做 │
│ 设置 │ ┃ 时间轨 事项     │    └────────────────────┘
└──────┴──────────────────┘
```

## 标志性元素：时间轨

每个事项左侧使用一条 3 像素时间轨：普通事项为雾蓝、今日必做为朱砂、完成为松针。轨道底部的小刻度表示提醒仍在运行。它编码真实状态，不作为无意义装饰。

未来界面继续围绕时间轨演化，而不是为邮箱、甘特图和云空间分别建立互不相关的卡片模板：

- 邮件提醒使用“投递路径”表达事件经过提醒方案后进入系统通知或邮件渠道，路径状态直接显示启用、等待、成功或失败。
- 甘特图将事项左侧时间轨横向展开为时间画布，普通、持续、月度和年度事件沿用同一状态颜色与刻度语言。
- 账户与云空间使用一条克制的“本机—云端”同步轨显示本机已保存、等待上传、已同步和冲突，不使用与实际状态无关的渐变、勋章或营销数字。

这是本产品允许的主要视觉风险：用一套连续时间/投递轨贯穿列表、提醒和同步状态。其他区域保持安静、紧凑，让用户先读到事项和下一次动作。

## 版本界面的单一任务

| 版本界面 | 主要用户 | 页面唯一任务 |
| --- | --- | --- |
| 邮件提醒 | 需要在离开电脑后仍收到重要事项的个人用户 | 看清哪些事项会发到哪个地址，并能安全测试一次 |
| 只读甘特图 | 需要回看日常、月度和年度安排的个人用户 | 在同一时间轴上看清事件范围与下一周期 |
| 账户与云空间 | 在多台电脑使用闪记的个人用户 | 判断本机数据是否安全同步，并处理空间或恢复问题 |

进入每个版本实现前，应在本文件补充该页面的 ASCII 草图和复核结论；若设计可无差别套用到任意待办产品，必须先重新设计。

## v0.7.1 数据恢复门禁

### 第一轮：对象、任务与视觉方案

- 具体用户：覆盖更新、重装或移动安装目录后，打开闪记却暂时看不到原事项的既有用户。
- 页面唯一任务：确认原数据仍然存在，并把经过校验的原数据恢复到当前稳定位置；完成前不得进入看似正常的空事项列表。
- 色彩 token：继续使用工作台 `#E9EDF2`、纸白 `#F9FAFB`、墨色 `#17202A`、雾蓝 `#7D91A6`、松针 `#2F6F62` 和朱砂 `#D94B35`。朱砂只标识数据连续性中断，松针只标识校验通过。
- 字体 token：标题沿用 `Bahnschrift` / `PingFang SC` / `Microsoft YaHei`；正文使用系统中文无衬线；记录数、更新时间和默认收起的路径使用 `Cascadia Mono` / `SFMono-Regular` / 等宽回退。
- 布局 token：主窗口内使用单列窄内容区，正文最大宽度 `620px`；状态、数据摘要和动作从上到下排列，首个可用动作获得自然键盘焦点，不使用遮挡式弹窗。
- 标志性元素：把事项左侧的 3 像素时间轨扩展为“原位置—已校验—当前位置”的数据连续轨。节点只编码真实检查结果，不显示虚构进度。

```text
┌──────────────────────────────────────────────┐
│ 闪记                                         │
│                                              │
│ ┃ 找到原来的数据                            │
│ ┃  128 项记录 · 2026/09/01 18:20            │
│ ┃  ✓ 已通过完整性与版本检查                 │
│ ┗━━━━━━ 当前数据位置等待恢复                 │
│                                              │
│ [恢复原数据并重新启动]  [打开原数据位置]     │
│ ▸ 诊断信息                                  │
└──────────────────────────────────────────────┘
```

状态文案必须回答三件事：发生了什么、原内容是否安全、接下来可以做什么。扫描时显示“正在检查本机数据”；找到时显示记录数和最近更新时间；只读、损坏、版本过新或备份失败时明确停止写入，并提供重试、打开数据位置和复制去敏诊断信息。路径只在用户主动展开时完整展示。

### 第二轮：产品原则复核与删减

- 删除通用红色警告卡、大图标、百分比进度条和“数据库/schema/迁移”等主界面术语；它们不能帮助用户恢复内容，也会让界面像安装器错误页。
- 恢复前不展示主导航、空事项列表、快速新增或提醒入口，避免用户误以为旧数据已经丢失并在新空库继续记录。
- 多个候选来源按最近更新时间排序，但不预选覆盖；每份只显示记录数、更新时间和“校验通过”，完整路径放入诊断信息。
- 恢复是唯一主按钮；“打开原数据位置”和“复制诊断信息”为次级动作。按钮、进度和完成反馈使用同一动词“恢复原数据”。
- 加载、找到、不可读取、恢复中和恢复失败均使用固定高度的状态区，避免内容跳动；减少动态效果时不使用轨道动画。
- 键盘焦点、高对比度和屏幕阅读器不依赖颜色：数据轨节点同时包含文字状态，错误区使用 `role="alert"`，进行中状态使用 `role="status"`。

复核结论：该界面把闪记已有的时间轨转换为真实的数据连续性轨，仍然服务于“先可靠记录，再逐步完善”，不是可套用于任意软件的备份卡片。实现应严格保持单一恢复任务，不借本版本增加仓库选择、自动合并或云同步入口。

## v0.8.0 本地数据仓库与安全归并

### 第一轮：对象、任务与视觉方案

- 具体用户：同时使用过安装版、便携版或更换过电脑，希望把分散记录放进一个个人仓库的单人用户。
- 页面唯一任务：看清本机、个人仓库和已发现来源之间的差异，确认后安全归并；仓库不可用时继续明确本机仍可记录。
- 色彩 token：沿用工作台 `#E9EDF2`、纸白 `#F9FAFB`、墨色 `#17202A`、雾蓝 `#7D91A6`、松针 `#2F6F62` 和朱砂 `#D94B35`；另用浅轨底 `#D8E0E8` 表示尚未流入本机的数据段，不新增营销渐变。
- 字体 token：标题继续使用 `Bahnschrift` / 中文窄体回退，正文为系统无衬线；修订数、冲突数、更新时间和校验摘要使用等宽字体。
- 布局 token：设置页中的宽内容区分为“本机事实源—个人仓库—待处理来源”三段，选择位置与归并预览均在同一上下文内完成，不跳转文件管理器后失去当前状态。
- 标志性元素：“来源汇流轨”。每个来源是一条细轨，在确认归并后汇入本机事实源；冲突处轨道分叉并显示“保留两份”，不以标题相似度伪装去重。

```text
┌─ 数据仓库 ──────────────────────────────────┐
│ 本机事实源  ━━━━━━━━━━━━━●  286 项 · 可继续记录 │
│                         ┃                    │
│ 个人仓库    ─────── 版本包┛  [选择仓库位置]   │
│                                              │
│ 发现来源    旧便携版 ──┬─ 18 项新增           │
│                       └─ 2 项冲突（保留两份） │
│                [预览并归并到本机]             │
└──────────────────────────────────────────────┘
```

失败状态固定回答：本机记录是否安全、仓库是否可用、哪些内容仍等待归并、下一步是重试还是更换位置。仓库断开、只读或包损坏时，主轨仍停在“本机已保存”，不得把快速记录误标为失败。

### 第二轮：产品原则复核与删减

- 删除“存储健康分数”、环形容量图和大号记录总数；它们像通用云盘仪表盘，不能帮助用户判断一次归并。
- 不直接把 SQLite 放进同步盘或移动介质；界面只称“个人仓库”，并明确本机始终保留可工作的数据。
- 不自动选中“最新文件”，不按标题合并；预览只显示新增、相同修订、冲突和删除记录数量，冲突默认保留两份。
- 选择、更换和停用仓库都使用“复制—校验—切换”的同一动作语言。永久清理旧包不属于本版本，也不放危险按钮。
- 路径默认单行省略，完整路径放在可复制详情中；诊断不含正文、备注、凭据或绝对路径之外的内容摘要。
- 高对比度下用实线、双线和分叉形状区分状态；减少动态效果时汇流轨不播放流动动画。

复核结论：来源汇流轨只适用于闪记“多份离线记录回到本机事实源”的真实语义，不是可替换成任意备份产品的卡片列表。

## v0.9.0 邮件提醒投递工作台

### 第一轮：对象、任务与视觉方案

- 具体用户：已经使用本机提醒，但需要重要事项在离开电脑时发到自己邮箱的个人用户。
- 页面唯一任务：看清“哪些事项、在何时、通过哪个地址发送”，安全完成一次测试后再启用规则。
- 色彩 token：继续使用六个基线色；松针只表示服务器已接受，雾蓝表示等待本机发送，朱砂表示需要用户处理，纸白承载规则编辑。
- 字体 token：标题与正文沿用基线；地址、策略时点和最近投递时间使用等宽字体。邮件正文使用系统正文栈，保证不同客户端可读，不引入远程字体。
- 布局 token：把服务器身份、收件地址、投递规则和最近结果分成从左到右/从上到下的真实投递顺序；窄窗口折成纵向但顺序不变。
- 标志性元素：“投递路径轨”。事件类型/类型/标签先进入提醒方案，再进入系统通知或邮件渠道；每个节点显示启用、等待、成功、失败之一。

```text
┌─ 邮件提醒 ──────────────────────────────────┐
│ 条件             投递策略          收件地址  │
│ [今日必做] ━━━● [每天第一次] ━━━● me@…      │
│                本机先保存          已测试 ✓  │
│                                              │
│ 最近结果：服务器已接受 · 09/03 08:20         │
│ [发送测试邮件]                 [保存邮件规则] │
└──────────────────────────────────────────────┘
```

邮件样式采用“桌面便笺抄送件”：纯色标题条、事项标题、计划时间、事件类型和“回到闪记处理”提示。HTML 与纯文本同时生成，不嵌入跟踪像素、远程图片、附件或凭据；失败邮件不把正文写入日志。

### 第二轮：产品原则复核与删减

- 删除营销邮件预览、设备插画、打开率和送达率图表；闪记只能确认服务器是否接受，不能声称用户已经阅读。
- 不把邮件做成第六种提醒方案；条件、触发时机、渠道和地址在界面中保持四个独立字段。
- 规则编辑只允许事件类型、单选类型、标签三类条件；同一投递命中多条规则时由稳定键去重，不让用户手工理解去重顺序。
- 未通过连接测试时可以保存草稿配置，但不能启用投递规则；认证、断网和服务器拒绝分别给出下一步，并明确事项仍在本机。
- “每次计划提醒”旁显示可能产生较多邮件的就地说明；默认策略为“首次到期”，不会继承旧版高频开关造成突增。
- 邮件本体在深色客户端仍保持浅色安全底，并用边框而非阴影建立层次；纯文本版本保留全部关键信息。

复核结论：投递路径把闪记已有的提醒计划真实映射到邮件，而不是常见的 SMTP 表单加几张状态卡；设置顺序与后台持久化模型一致。

## v0.10.0 只读时间画布

### 第一轮：对象、任务与视觉方案

- 具体用户：积累了普通、预警、持续、月度和年度事项，需要在一个时间范围内回看安排的个人用户。
- 页面唯一任务：在不修改任何事项的前提下，看清它们占据的时间、当前所在位置和下一周期，并能打开原事项详情。
- 色彩 token：基线六色全部沿用；周末底纹 `#E2E7EC`、今日线朱砂 `#D94B35`、未排期底 `#F1F3F5`。事件颜色仍由状态和类型语义决定，不随机生成彩色条。
- 字体 token：画布标题使用 `Bahnschrift`；日期刻度与时点使用等宽字体；事项名称仍用系统正文，缩放后不小于 `12px`。
- 布局 token：主导航增加“时间画布”。顶部仅保留日/周/月/年缩放、前后移动、回到今天和筛选；左侧为事项名称，右侧为可横向滚动的时间轴，未排期固定在画布底部。
- 标志性元素：把事项列表的 3px 竖向时间轨旋转并展开成横向时间条。里程碑为短刻度、持续事件为实线区间、预警为前段虚线加目标点、月/年周期为重复刻度。

```text
┌─ 时间画布 ──────────────────────────────────┐
│ [日][周][月][年]   ‹  2026 年 9 月  › [今天] │
│                  01  08  15  22  29          │
│ 发布准备          ┄┄┄┄┄┄●                    │
│ 出差                    ━━━━━━━               │
│ 月度复盘                 │       │             │
│ 今日必做                     ●                 │
│ ──────────────── 今天 ───────┼────────────── │
│ 未排期  3 项 [展开]                            │
└──────────────────────────────────────────────┘
```

### 第二轮：产品原则复核与删减

- 删除拖拽把手、依赖箭头、关键路径、资源利用率和项目完成百分比；首版只读，任何看似可拖动的形状都会误导。
- 不在 UI 自行推算月末、闰日或夏令时；后端返回画布投影，前端只定位和展示，点击条目仍回到现有事项详情。
- 不把无起止时间的事项拉成虚假长条；它们进入“未排期”区，到期事项只显示里程碑。
- 缩放改变可见范围和刻度密度，不修改业务时间；筛选继续复用状态、事件类型、类型和标签语义。
- 横向滚动区域与事项名称列保持对齐；键盘可逐项移动焦点并按 Enter 打开，焦点环不依赖条形颜色。
- 只在今日线和选中事项使用强调，移除网格阴影、渐变填充和无业务意义的浮动统计卡。

复核结论：时间画布是现有时间轨的方向性延展，能从条形形状直接读出七种事件的时间语义，同时严格保持只读。

### 统一实施后的浏览器复核（2026-09-05）

- 使用真实业务示例依次检查主事项列表、空/有数据的时间画布、邮件规则空状态与编辑器、仓库未配置状态，以及 `760 × 560` 窄窗口。
- 时间画布的今日线只在今天位于当前可见范围时出现；范围外通过显式透明度 token 隐藏，避免贴在画布边缘制造错误日期暗示。
- 收起侧栏后所有图标按钮保留可访问名称和悬停说明；键盘焦点顺序仍按事项、时间画布、邮件提醒、数据仓库和设置排列。
- 邮件、仓库和画布均覆盖成功、空状态、加载、失败或恢复入口；邮件连接错误按凭据缺失、配置错误和网络失败转换为用户可行动文案。
- 浅色、深色、高对比度和减少动态效果继续使用同一信息层级；浏览器控制台复核为零错误、零警告。

## v0.10.1 Windows 安装向导中文补齐

### 第一轮：对象、任务与视觉方案

- 具体用户：首次安装或更新闪记的中文 Windows 用户。
- 唯一任务：看懂当前步骤与影响，安全完成安装或退出；卸载时明确是否删除本机数据。
- 色彩、字体、布局 token：保留原生向导的系统控件颜色、对话框字体、间距和底部导航；不引入网页字体、动画或自绘控件，系统高对比度与缩放继续由原生控件承接。
