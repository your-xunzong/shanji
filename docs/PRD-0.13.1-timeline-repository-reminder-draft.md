# v0.13.1 状态甘特图、个人仓库闭环与角落提醒修复草案

> 状态：2026-09-08 用户已确认并完成实施，待统一验收
> 草案日期：2026-09-08
> 指定版本：`0.13.1`。包含甘特图展示增强、个人仓库闭环与提醒窗缺陷修复；该版本可作为 v0.12.0 自动更新的第一个真实验收目标。

## 1. 目标

1. 让用户一眼看出事项从创建、开始、截止到逾期或完成的阶段变化，而不是只看到一根含义单一的横条。
2. 让“个人仓库”明确完成“本机写入仓库”和“其他设备汇入本机”两个方向，并在汇入后立即看到结果。
3. 让屏幕角落提醒窗在正常、载荷缺失和系统隐藏失败时始终保留可用的关闭路径，同时不误改事项状态。

## 2. 当前问题与原因

### 2.1 甘特图

- 当前后端已返回创建至截止/今天的生命周期区间、活动/预警高亮和整体状态，但前端把每个区间绘制成一根主色条。
- 已记录、尚未开始、活动中、已过截止和已完成没有在同一条上形成阶段分段；截止只存在于文字中，用户难以快速区分“还在进行”和“已经逾期多久”。

### 2.2 个人仓库

- 选择仓库位置目前只建立并保存 `shanji-repository` 目录，不立即生成本机数据包，因此刚配置后仓库可能仍为空。
- “预览本次同步”只预览其他设备包；用户必须继续确认同步，系统才会在归并结束后写出本机包，这个方向在界面中没有讲清楚。
- 同步成功后只重新读取当前筛选下的事项；类型、标签、提醒中心数量和当前筛选之外的新事项没有完整反馈，容易被理解为没有汇入。

### 2.3 屏幕角落提醒窗

- 当前关闭动作先清空前端提醒队列，再请求系统隐藏窗口；若隐藏失败，窗口仍在，但事项内容和关闭按钮已经消失。
- 空载荷状态只有“提醒准备就绪”，没有关闭操作；关闭失败也没有可重试提示。
- 关闭只应关闭本次窗口，不应偷偷完成、暂停、确认或稍后提醒该事项；后续是否再次出现必须继续服从事项自己的提醒方案。

## 3. 范围

### 3.1 分段状态甘特图

每条事项保留同一行，通过相邻、无缝的状态段表达时间，而不是拆成多行：

```text
事项名称 │ 已记录 ━━━ 进行中 ━━━│截止│//// 逾期至今天
完成事项 │ 已记录 ━━━ 进行中 ━ ✓ 已完成
周期事项 │ [本周期分段]   [下一周期分段]   [后续预览]
```

- **已记录段**：从创建时间到业务开始时间；没有独立开始时间时可为零宽，不凭空制造阶段。
- **进行中段**：从业务开始时间到截止/目标/结束时间；普通事项没有开始时间时，从创建时间开始。
- **预警段 / 活动段**：继续作为主条内部的业务强调，但改为与状态段边界对齐，不覆盖截止标记。
- **逾期段**：事项仍未完成且已过截止时，从原截止延伸到当前时间；使用克制的红色斜纹，并在原截止位置保留清晰竖向刻痕。这样既保留原截止，也能看出逾期持续多久。
- **完成状态**：有 `completed_at` 时显示完成刻点。提前完成时，完成点之后到原截止使用低饱和绿色；逾期完成时，截止到完成点显示逾期段，条在完成点结束。没有可靠完成时间的旧数据只将原生命周期条标为已完成，不猜测完成日期。
- **无截止事项**：从创建时间延伸到今天，末端使用开放标记并写“进行至今天”，不伪造截止。
- **月度/年度事项**：仍在同一行按周期分段；当前周期可显示进行中或逾期，未来预览只用轮廓，不显示成已经发生的状态。
- 点击任意状态段仍打开同一事项；悬浮和键盘焦点说明该段名称、起止时间、截止与完成情况。

#### 数据边界

- 只使用已经持久化的 `created_at`、开始/活动/目标/截止/结束、`completed_at` 和当前状态，不新增或推断暂停历史、重新打开历史、完成百分比。
- 甘特图保持只读，不因浏览而修改事项、提醒计划或业务时间；本版不增加数据库迁移。

### 3.2 个人仓库双向闭环

界面明确显示数据方向：

```text
这台设备 ──写入本机快照──▶ 个人仓库 ──预览后汇入──▶ 这台设备
```

- 选择并确认仓库位置后，立即以原子临时文件生成本机快照；成功文案明确写出“已写入 N 条本机记录”，不再只说路径可读写。
- 若首次快照写入失败，保留本机数据库不变，仓库状态显示“位置已保存，但本机快照尚未写入”，提供“重新写入”，不得谎报同步完成。
- 主操作改为“检查其他设备的数据”；预览明确列出新增、已有、冲突和删除记录。
- 用户确认后执行：创建本机恢复备份 → 事务汇入其他设备 → 校验 → 写出包含归并结果的新本机快照。归并事务失败不得留下部分汇入结果；归并成功但快照写出失败时保留已汇入数据与恢复备份，并明确提示单独重试快照。
- 成功后完整刷新事项列表、类型、标签、待选择事件数量、提醒中心与托盘数量；结果卡显示实际汇入数、冲突副本数和删除数。
- 当前筛选隐藏了新记录时，结果明确提示，并提供“查看全部事项”；不能只显示“同步完成”。
- 没有其他设备的新数据时，仍可更新本机快照，结果写“仓库已更新，本机没有需要汇入的新记录”。
- 保留预览与二次确认；不自动把仓库中的未知、损坏或冲突数据静默写入本机。

### 3.3 屏幕角落提醒窗关闭闭环

- 右上角按钮文案和可访问名称统一为“关闭本次提醒窗”；含义是隐藏这次窗口，不完成、不暂停、不确认、不稍后提醒事项。
- 调整顺序为：先请求系统隐藏成功，再从窗口队列移除内容。隐藏失败时保留事项、关闭按钮和三个业务操作，并显示“提醒窗没有关闭，可重试或打开闪记”。
- 空载荷或启动竞态时仍显示关闭按钮，不允许留下无法操作的“提醒准备就绪”窗口。
- 关闭按钮放在非拖动命中区，提供至少 36×36px 点击范围、明确悬浮/键盘焦点；用户点击过窗口后可用 `Esc` 关闭，中文输入法组合态不触发。
- 系统标题栏关闭请求与应用内关闭按钮使用同一隐藏语义。相同提醒事件不得因隐藏失败、30 秒健康检查或窗口重新加载立刻重复入队。
- 若事项自己的下一提醒时间到达，角落窗仍可再次出现；用户要停止后续提醒时使用“完成”“15 分钟后提醒”或主界面的“暂停提醒”。

## 4. 非目标

- 不增加拖动改期、依赖关系、进度百分比、资源负载或项目管理状态。
- 不把个人仓库改成云账号、实时文件监听、常驻高频轮询或多端自动覆盖；仍由用户发起汇入。
- 不改变事项自身的提醒频率、提醒中心确认语义或今日必做规则。
- 不读取或记录用户事项正文用于诊断；同步日志继续只保存计数、哈希和去敏错误。

## 5. 失败与恢复

- 甘特图某条时间损坏时继续进入“时间待核对”，其他事项照常显示；刷新失败保留上一张有效画布。
- 仓库目录消失、只读、空间不足、数据包损坏或 schema 过新时停止同步，说明本机数据是否已改变，并提供重新连接、重试或打开仓库位置。
- 汇入事务成功但新快照写出失败时，本机汇入结果仍必须可恢复；界面区分“本机已汇入，仓库快照待重试”，不得把两步混成成功。
- 角落窗隐藏失败时内容和操作保持可用；若窗口载荷丢失，可以关闭窗口或打开主界面，不显示内部命令和错误堆栈。

## 6. 跨平台差异

- 甘特图与个人仓库规则三平台一致；字体、滚动条和文件选择器只允许外观降级，不改变数据语义。
- Windows、macOS、Linux 的角落窗均使用同一关闭状态机；窗口不抢焦点仍是默认。Wayland 窗口定位或置顶不可靠时允许由桌面环境决定位置，但必须能关闭并保留提醒中心兜底。
- Windows 先完成真实安装包验证；macOS/Linux 需实机验证窗口关闭、同步盘文件原子替换和权限失败恢复。

## 7. 前端两轮设计结论

### 第一轮：具体方向

- **用户**：同时管理短期提醒和跨天事项、需要在几秒内判断“还没开始、正在进行、逾期多久”的个人工作者。
- **页面唯一任务**：在同一时间轴上辨认每条事项当前处于哪个阶段，并能直接打开原事项处理。
- **色彩 token**：纸面冷白 `#F7F9FC`、正文深墨 `#223349`、记录蓝灰 `#AFC1D6`、进行深蓝 `#315E91`、完成松绿 `#397565`、逾期朱红 `#B84040`。
- **字体 token**：中文标题/正文沿用 `Microsoft YaHei UI`、`PingFang SC`、`Noto Sans CJK SC`；日期和时点使用 `Cascadia Mono` / `SFMono-Regular` 回退，正文 14px、刻度和状态 12px。
- **布局**：保留固定事项列、固定日期表头和 44px 行高，不添加仪表盘卡片；状态只在条内编码，筛选和说明保持安静。
- **标志性元素**：无间隙“缝合式状态条”，在真实截止位置留下窄刻痕；逾期尾段使用斜纹延伸到今天。这一处承担全部记忆点。

### 第二轮：对产品原则的自检与删减

- 六种颜色如果同时用于页面装饰会变成通用项目管理彩虹，因此颜色只进入时间条、截止刻痕和小型图例；事项类型、筛选及背景保持中性。
- 不使用渐变进度条、百分比、发光阴影和额外动画，因为本产品没有可靠进度数据；不同状态用实线、低饱和填充、斜纹和边界形状共同表达，兼顾高对比度与色觉差异。
- 仓库页不增加新的统计卡阵列，改用一条真实双向资料流和结果句；提醒窗不重新造型，只修正关闭命中区、状态顺序和恢复文案。
- 保留的视觉风险只有“逾期斜纹尾段”，理由是它能在不扩大红色面积的前提下表达时间仍在继续；减少动态效果下完全静态，高对比度下改用系统边框/纹理。

## 8. 验收标准

### 甘特图

1. 固定时钟覆盖未开始、进行中、开放事项、未完成逾期、提前完成、逾期完成和缺失完成时间，分段起止、截止刻痕与文字一致。
2. 日/周/月/年及月末、年末、闰日、夏令时、时区变化和时间回拨不产生负宽度、重叠错位或重复周期段。
3. 只靠形状/边框也能区分逾期和完成；键盘能逐段读取，760×560、浅色、深色、高对比度和减少动态效果无截断。
4. 10 万条压力回归不明显降低现有投影与可见行渲染预算。

### 个人仓库

1. 新选择空仓库后无需第二次操作即可看到本机 `.sjpack`，包内记录数量与本机一致；写入失败不显示成功。
2. 两个独立实例完成“设备 A 写入 → 设备 B 预览 → 确认汇入”，B 的全部事项、类型、标签和提醒状态重新读取；当前筛选隐藏记录时可一键查看全部。
3. 相同修订重复同步幂等，分歧内容保留冲突副本；取消确认、目录只读、空间不足、损坏包和事务失败不丢本机数据。
4. 同步成功与本机包写出失败能被分别表达和恢复，日志与界面不泄露正文、凭据或内部 SQL。

### 角落提醒窗

1. 连续打开 20 次测试窗，鼠标点击关闭均隐藏；关闭不改变事项的完成、暂停、确认和下一提醒计划。
2. 模拟隐藏失败时事项与关闭按钮仍在，重试成功后隐藏；空载荷窗口也可以关闭。
3. 点击窗后 `Esc` 可关闭，IME 组合态不触发；关闭按钮不被拖动区吞掉，焦点和高对比度边框可见。
4. 同一事件在关闭、窗口重载、健康检查和系统时间回拨时不立即重复弹出；到达下一次真实计划后仍按事项方案提醒。

## 9. 需要确认的行为变化

- 未完成逾期事项将在原截止之后增加“逾期至今天”的尾段；原截止仍用刻痕保留。这会替代 v0.11.0“逾期条停在截止、不延长到今天”的显示规则。
- 选择个人仓库后会立即写出本机快照，但不会未经预览自动汇入其他设备数据。
- “关闭本次提醒窗”只隐藏窗口，未来真实提醒时间到达时仍会再次出现。
