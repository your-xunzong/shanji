# 闪记 v0.13.2 提醒继承、状态恢复、周期小结与仓库去重 PRD 草案

> 状态：待用户确认，确认前不修改正式 PRD、功能代码、数据库或版本号  
> 草案日期：2026-09-15  
> 目标版本：v0.13.2  
> 版本说明：按用户确认的版本范围，本草案作为当前 v0.13.2 的需求修订；实施和发布时必须把既有 Windows 原生通知窄宽度修复与本草案能力放入同一份 v0.13.2 变更说明、安装包和验收记录，不得用旧产物冒充更新后的 v0.13.2。

## 1. 一页结论

本版本解决五个连续问题：

1. 事件类型和“重要”标记都有可持久化的默认提醒方案；用户在后台改变事件类型或重要状态时，事项立即显示将要套用的默认方案，仍可随后单独覆盖。
2. 已标记完成的事项可在后台明确恢复为未完成，原内容和历史保留，未来提醒从当前状态安全重算。
3. 用户可用自己提供的 `.docx` 模板，按月或季度生成本地 Word 小结；模板通过清晰占位符决定内容落点和格式。
4. 个人仓库对内容完全一致的重复冲突安全合并，对确有差异的冲突提供一次性解决闭环；解决结果随仓库同步，不在下一次同步重新制造相同冲突。
5. “重复”提醒可单独开启“显示完整事项信息”；该开关只改变重复方案的通知内容，不改变频率、渠道或其他提醒方案。

快速录入主链路保持不变：`全局唤起 → 输入 → Enter → 可靠落盘`。本版不把事件类型、提醒方案、模板或仓库选择带入快速录入必填路径。

## 2. 背景与现状差异

- 当前正式 PRD 已规定“选择事件类型时自动套用该类型的默认提醒方案，并允许立即覆盖”。现有事项编辑器只改变事件类型，不同步刷新提醒方案，属于已确认行为未完整落地。
- 当前已有七种事件类型的默认提醒方案，但“重要”只是独立布尔标记，没有自己的默认提醒方案和优先级。
- 当前事项保存的是最终提醒方案，界面无法解释它是自动继承还是用户单独修改；后续默认值变化也无法安全判断哪些事项可以跟随。
- 当前个人仓库采用“无法证明单边变化时保留完整冲突副本”的保守策略，避免丢数据，但缺少面向已有冲突的解决和去重闭环。
- 当前可导出 Excel，没有按用户 Word 模板生成月度或季度小结的能力。
- 当前系统通知主要显示事项标题和到期信息，没有只针对“重复”方案的详情展示开关。

## 3. 目标

1. 用户只选择事件类型或勾选“重要”，系统就能可靠匹配默认提醒方案，无需重复选择。
2. 用户明确选择某个提醒方案后，该事项保留单独设置，不被同一事件类型默认值的后续修改静默覆盖。
3. 自动套用的来源可见、可恢复，保存失败时不出现事件类型与提醒方案不一致的半保存状态。
4. 已完成事项可从后台恢复为未完成，恢复动作可审计、可失败回滚且不补发历史提醒。
5. 月度、季度小结完全在本机生成，模板格式由用户掌控，数据范围和生成结果可核对。
6. 仓库同步不反复生成相同冲突；去重不以标题或修改时间为唯一依据，不静默丢弃有差异的内容。
7. 重复方案可以展示更多事项信息，同时保留隐私边界和跨平台降级。

## 4. 范围

### 4.1 本版包含

- 七种事件类型默认提醒方案的自动匹配修复。
- “重要事项默认提醒方案”设置。
- 单事项提醒方案来源：事件类型默认、重要默认、单独设置、旧数据保留。
- “恢复默认提醒方案”操作。
- 已完成事项在后台恢复为未完成，并重建未来提醒。
- 月度或季度 `.docx` 小结生成、模板选择、模板校验、生成预览摘要和本地保存。
- 个人仓库完全相同副本自动去重、差异冲突人工解决、解决结果持久化及跨设备传播。
- “重复提醒显示完整事项信息”设置，默认关闭。
- 数据迁移、备份、审计、幂等、失败恢复和三平台降级。

### 4.2 非目标

- 不新增账号、云空间、团队协作、AI 云端总结、遥测或默认联网。
- 不根据标题相似、正文相似或更新时间接近自动删除事项。
- 不自动改写用户提供的 Word 模板，也不在模板缺少或校验失败时生成格式未知的替代文件。
- 不提供 Word 在线编辑器、多人模板库、PDF 转换、邮件自动发送小结或定时自动生成。
- 不改变“强调、一次性、强制、自定义”方案的通知内容和展示方式。
- 不改变提醒频率、重复时点、勿扰规则、邮件投递策略或快速录入步骤。
- 不保证操作系统原生通知一定完整展开；系统可能按平台、缩放或通知中心宽度截断内容。

## 5. 关键业务定义

### 5.1 默认提醒方案优先级

当系统需要自动选择提醒方案时，按以下顺序计算：

1. 用户刚刚为当前事项明确选择的方案：记为“单独设置”，优先级最高。
2. 事项已勾选“重要”且本次需要重新匹配：使用“重要事项默认提醒方案”。
3. 事项已有事件类型：使用该事件类型的默认提醒方案。
4. 事项尚未选择事件类型：沿用现有待选择事件类型的“重复”规则。

“重要”是独立标记，不成为第八种事件类型；事件类型、类型、标签和用户原文均保持原语义。

### 5.2 提醒方案来源

每条事项保存一个明确来源：

| 来源 | 用户可见文案 | 行为 |
| --- | --- | --- |
| 事件类型默认 | `跟随“普通”默认：强制` | 由本次事件类型选择自动套用 |
| 重要默认 | `跟随“重要事项”默认：强调` | 由本次开启重要标记自动套用 |
| 单独设置 | `已为此事项单独设置：重复` | 不因默认值后续变化而静默修改 |
| 旧数据保留 | `沿用升级前设置：重复` | 升级不猜测来源、不改计划；用户可主动恢复默认 |

来源只说明方案如何确定，不新增一套提醒频率。

### 5.3 自动重新匹配时机

- 从“待选择事件类型”改为任一事件类型：立即套用该类型默认；若同时为重要，套用重要默认。
- 从一种事件类型改为另一种：立即套用新类型默认；若为重要，套用重要默认。
- 从未勾选改为“重要”：立即套用重要默认。
- 从“重要”改为未勾选：立即套用当前事件类型默认；尚未选类型则使用待选择事件规则。
- 用户随后手动选择提醒方案：来源改为“单独设置”。
- 只修改标题、备注、类型、标签或时间：不得重置已经单独设置的提醒方案。
- 用户再次选中当前已经选定的同一事件类型：不得把单独设置覆盖掉。
- 用户点击“恢复默认”：按当前重要状态和事件类型重新计算，并在保存前展示结果。
- 修改后台默认方案：只影响之后新建、之后切换类型/重要状态或主动恢复默认的事项；不批量修改既有事项。

### 5.4 示例

1. “吃饭”尚未选择事件类型，当前按待选择规则使用“重复”。
2. 用户把后台“普通”的默认方案改为“强制”；既有事项不被批量修改。
3. 用户编辑“吃饭”，把事件类型改成“普通”；编辑器立即显示`跟随“普通”默认：强制`。
4. 用户保存后，事件类型和强制方案在同一事务中生效。
5. 用户以后觉得强制过于打扰，把该事项改为“重复”；来源变为`已为此事项单独设置：重复`。
6. 之后后台“普通”默认再次变化时，“吃饭”仍保持重复，除非用户切换事件类型或点击“恢复默认”。

## 6. 功能需求

### 6.1 提醒默认值与单事项覆盖

| 编号 | 需求 | 验收要点 |
| --- | --- | --- |
| RMD-1321 | 事件类型自动匹配 | 编辑器切换事件类型后，在保存前立即刷新方案、相关字段和来源说明 |
| RMD-1322 | 重要事项默认方案 | 设置页可从重复、强调、一次性、强制、自定义中选择并持久化默认值 |
| RMD-1323 | 来源可见 | 事项编辑器明确显示当前方案来自事件类型默认、重要默认、单独设置或旧数据保留 |
| RMD-1324 | 单独覆盖 | 用户手动改方案后只影响当前事项，不反向修改任何默认值 |
| RMD-1325 | 恢复默认 | 单独设置和旧数据可一键恢复当前适用默认，保存前可见新结果 |
| RMD-1326 | 原子保存 | 事件类型、重要状态、提醒方案、未来计划和审计事件一次事务提交；失败全部回滚 |
| RMD-1327 | 未来计划 | 方案变化只重算未来提醒，不补发历史触发点，不复用旧幂等键制造重复通知 |

切换到需要额外参数的方案时使用可靠默认值承接，参数在提醒方案下方展开：

- 重复：复制当前两个默认时点。
- 强调或强制：复制当前持久化间隔。
- 自定义：先保留该事项仍然适用且合法的已有参数；缺少必需值时明确标记“需要补充”，不能假装已保存。

### 6.2 已完成事项恢复为未完成

- 后台“已完成”筛选和事项详情为每条已完成事项提供`恢复为未完成`操作；不得只写容易与回收站混淆的“恢复”。
- 恢复后状态从 `DONE` 变为 `OPEN`，清除当前完成时间，但保留创建时间、原截止时间、事件类型、类型、标签、重要标记、提醒方案、提醒来源和历史完成审计记录。
- 恢复不是新建或复制事项，事项稳定 ID 不变；个人仓库将该状态变化作为同一事项的新修订传播。
- 恢复时从当前时间重新计算下一次未来提醒，不补发完成期间或恢复前已经错过的历史提醒。
- 原截止时间已经过去时，事项恢复后显示为“已逾期”，不得静默把截止时间移动到今天或下一工作日；用户可随后使用现有“调整时间”。
- 一次性方案的有效日期已经结束时，恢复后保持未完成和逾期，但不补发已经失效的一次性通知；界面提示“原提醒时间已过，可调整时间重新提醒”。
- 月度或年度事项恢复整个系列时，应恢复事项本身；已经明确完成的历史周期保持审计记录，不伪造未发生周期。若只需恢复某一期，需另行评审，不在本版混入。
- `恢复为未完成`、未来计划重建和审计事件在同一事务完成；失败时事项继续保持已完成，界面显示“没有恢复，事项仍是已完成；可以重试”。
- 恢复成功后提供短时`重新标记完成`动作；该动作使用正常完成流程，不删除恢复历史。
- Windows、macOS、Linux 使用相同状态与提醒语义，不新增系统权限。

### 6.3 月度、季度 Word 小结

#### 6.3.1 生成入口与数据范围

- 入口放在“数据与小结”，不加入快速录入窗口。
- 用户选择“小结周期：月度 / 季度”和目标月份或季度；时间范围按当前持久化时区策略计算。
- 默认统计该期间创建、到期、完成或仍逾期的相关事项；回收站和永久删除内容不进入小结。
- 生成前显示：周期、模板名称、纳入事项数、完成数、未完成数、逾期数、重要事项数和保存位置。
- 生成是只读操作，不改变事项状态、提醒计划、仓库或模板原文件。
- 小结内容由本地确定性规则和数据库事实生成，不调用云端模型；任何叙述性文字都必须能由统计与事项状态复核。

#### 6.3.2 模板占位符写法

用户提供 `.docx` 后，在希望显示数据的位置直接输入占位符。占位符使用半角双花括号，例如 `{{period_label}}`。

放置规则：

- 封面标题或正文：放单值占位符。
- 统计表：在对应数值单元格放统计占位符。
- 事项明细表：保留一行作为“模板行”，在该行不同单元格放同一集合前缀的占位符；生成时复制整行并保留格式。
- 一个占位符必须作为连续文本输入，不能只给花括号或名称的一部分单独改字体、加批注或插入换行。
- MVP 只解析文档正文和正文中的表格；页眉、页脚、文本框、SmartArt、批注和公式域中的占位符不保证替换。

建议模板落点与首版占位符：

| 模板位置 | 占位符 | 内容 |
| --- | --- | --- |
| 封面标题 | `{{report_title}}` | 例如“2026 年 9 月月度小结” |
| 封面或页首 | `{{period_label}}` | 例如“2026 年第三季度” |
| 封面或页尾正文 | `{{generated_at}}` | 本地生成时间 |
| 概览段落 | `{{period_summary}}` | 由本地规则生成的简短事实小结 |
| 统计表 | `{{total_count}}` | 纳入事项总数 |
| 统计表 | `{{completed_count}}` | 本期完成数 |
| 统计表 | `{{open_count}}` | 期末未完成数 |
| 统计表 | `{{overdue_count}}` | 期末逾期数 |
| 统计表 | `{{important_count}}` | 重要事项数 |
| 统计表 | `{{completion_rate}}` | 完成率，分母和口径在预览中说明 |
| 事件类型汇总模板行 | `{{event_kind.name}}`、`{{event_kind.total}}`、`{{event_kind.completed}}` | 按七种事件类型复制行 |
| 类型汇总模板行 | `{{category.name}}`、`{{category.total}}`、`{{category.completed}}` | 按用户自定义类型复制行 |
| 已完成事项模板行 | `{{completed_item.title}}`、`{{completed_item.event_kind}}`、`{{completed_item.completed_at}}` | 每条已完成事项复制行 |
| 未完成事项模板行 | `{{open_item.title}}`、`{{open_item.due_at}}`、`{{open_item.status}}` | 每条期末未完成事项复制行 |
| 重要事项模板行 | `{{important_item.title}}`、`{{important_item.status}}`、`{{important_item.due_at}}` | 每条重要事项复制行 |

收到模板后，实施前应输出一份“占位符标注清单”，逐页告诉用户在何处放哪个占位符；未经确认不改变模板结构。

#### 6.3.3 模板校验与生成失败

- 选择模板后先只读校验文件是否为有效 `.docx`、占位符是否受支持、一个明细模板行是否混入多个集合前缀。
- 未识别占位符逐项列出；用户可以返回修改模板，原文件保持不变。
- 模板缺少某个可选区块时跳过该内容，不擅自新增页面；缺少所有可识别占位符时禁止生成。
- 输出先写临时文件，重新打开并校验成功后再原子移动到用户位置；失败时删除不完整临时文件，不留下冒充成功的文档。
- 保存失败时说明事项数据和模板原文件均未改变，并提供“重新选择位置”或“重试”。
- 用户文字写入 Word 时按普通文本处理，不解释为 XML、域代码、宏或外部链接。

### 6.4 个人仓库去重与冲突解决

#### 6.4.1 自动去重边界

- 仍以稳定实例 ID、事项 ID、来源修订、已见修订和内容摘要为主要依据。
- 对来源链可追溯且用户可见内容、状态、时间规则、标签关系和提醒计划完全一致的副本，允许自动合并为一条规范记录。
- 自动合并前创建一致性备份；重复副本不永久删除，而是记录为已合并、停止重复提醒并从默认事项列表隐藏，可从冲突历史查看来源。
- 标题相同但备注、状态、时间、重要标记、类型、标签或提醒方案任一不同，不视为完全重复。
- 不使用“最后修改时间较新的一条”自动覆盖另一条；设备时钟不能作为唯一胜负依据。

#### 6.4.2 差异冲突解决

- 同步预览分开显示“完全重复（将自动合并）”和“内容有差异（需要选择）”，不再把两者都计为冲突副本。
- 新增“处理仓库冲突”入口，按同一逻辑事项成组展示两个来源版本及不同字段。
- 用户可以选择“保留本机版本”“保留仓库版本”“两份都保留”或逐字段组成一个结果；任何会隐藏一份内容的选择都先展示影响。
- 解决结果在一个事务中写入规范事项、来源修订映射、解决记录、未来提醒和审计事件。
- 已解决的两组修订生成稳定解决指纹，并写入下一份仓库数据包；其他设备同步后不得再次把同一对修订创建为新冲突。
- 新的后续修订若再次发生双向修改，可以形成新的冲突，但必须与已经解决的旧冲突区分。
- 现有未解决冲突可运行一次“整理已有冲突”：完全相同者自动收束，有差异者进入处理列表。

#### 6.4.3 失败与恢复

- 预览、去重或解决失败时不改变运行库和仓库包；界面说明本机事项是否安全，并提供重试。
- 本机成功解决但仓库快照写入失败时，明确显示“本机已整理，仓库待更新”，保留可幂等重试的待写入状态。
- 仓库不可用不阻塞本机快速保存和提醒。
- 不自动清理用户手动放入仓库目录的未知文件；只管理闪记自己识别的数据包和内部状态。

### 6.5 重复提醒显示完整事项信息

- 设置位置：`设置 → 提醒显示 → 重复提醒`。
- 开关名称：`重复提醒显示完整事项信息`。
- 默认关闭，以保持升级前的通知内容和锁屏隐私边界。
- 开启后，只对提醒方案为“重复”的系统通知增加：事件类型、类型、标签、到期时间、本次提醒时点和下一次计划提醒；没有的字段不显示。
- 不显示备注全文、内部 ID、仓库状态、邮件地址、系统路径或诊断信息。
- 通知操作仍沿用平台已有的“完成”“稍后提醒”或点击正文打开事项；本版不增加第三个 Windows 按钮。
- 开关只改变通知内容，不启用系统持续提醒、不启用置顶窗、不改变每日两个时点、不改变邮件渠道。
- 格式化详情失败时降级为原有标题和到期时间通知，不能因此跳过本次提醒。
- Windows、macOS、Linux 使用同一内容规则，但原生通知最终可见行数由操作系统决定；被截断时点击通知打开完整事项详情。若用户需要不受原生通知宽度限制的完整界面，可继续单独启用现有应用置顶提醒窗。

## 7. 数据、迁移与技术边界

- 预计 SQLite schema 从 v11 升级到 v12；迁移前按既有机制创建一致性备份并在临时副本校验。
- 新增或等价保存：重要事项默认方案、事项提醒方案来源、重复详情通知开关、冲突解决指纹、规范事项映射和小结模板元数据。
- 升级时所有既有事项标记为“旧数据保留”，方案、重要标记、时间、未来计划和提醒历史原样保持；不得猜测并批量改成新默认。
- 七种既有默认提醒方案原样保留；新增重要默认建议初始值为“强调”，但只有新开启重要标记、切换类型或主动恢复默认时使用。
- 重复详情通知开关初始为关闭。
- Word 模板和生成文档不写入 SQLite 正文；仅在用户同意时保存模板路径、最近周期和输出目录偏好。模板不可用时不影响事项与提醒。
- Word 生成实现不得引入常驻运行时、后台服务或网络权限。若需要新增生产依赖，实施前补充 ADR，说明许可证、包体积、维护性和三平台支持。
- 所有领域计算、去重判断、模板数据准备和数据库写入由 Rust 层负责；UI 不直接执行 SQL。

## 8. 跨平台差异

| 能力 | Windows | macOS | Linux |
| --- | --- | --- | --- |
| 默认方案与重要优先级 | 完整支持 | 完整支持 | 完整支持 |
| 完成事项恢复 | 完整支持 | 完整支持 | 完整支持 |
| `.docx` 本地生成 | 完整支持，需实机检查 Word/WPS | 文件生成一致，需 Word/Pages 实机检查 | 文件生成一致，需 LibreOffice 实机检查 |
| 仓库去重与解决传播 | 完整支持 | 完整支持 | 完整支持；同步盘原子替换仍需实机检查 |
| 重复详情系统通知 | 内容规则一致，系统控制宽度与按钮 | 系统控制横幅/提醒样式 | 通知服务可能截断或忽略操作 |

任何平台无法完整展示通知时都只降级显示，不改变调度、事项状态或幂等语义。

## 9. 两轮界面设计草案

### 9.1 第一轮：对象、任务与 token

具体用户：已经积累多种事项，希望设置一次默认值、日常只处理例外，并需要定期复盘与跨设备整理的个人用户。

页面唯一任务：

- 提醒设置：看懂“系统自动选了什么”，并只在需要时为单条事项覆盖。
- 已完成列表：核对原事项状态，并在确实仍需处理时恢复为未完成。
- 数据与小结：选择周期和模板，核对范围后生成一份 Word。
- 仓库冲突：看清两份记录哪里不同，作出一次可恢复的决定。

视觉 token 沿用现有闪记设计，不新造一套控制台风格：

- 冷白 `#F7F9FC`：页面底色。
- 内容白 `#FFFFFF`：编辑与预览区域。
- 深墨 `#223349`：主要文字。
- 主蓝 `#315E91`：当前选择与主要动作。
- 完成绿 `#397565`：已继承、已校验、已解决。
- 风险红 `#B84040`：有差异、生成失败和需人工处理。
- 中文正文：`Microsoft YaHei UI` / `PingFang SC` / `Noto Sans CJK SC`，14px；数据和占位符：`Cascadia Mono` / `SFMono-Regular`，12px。
- 布局：抽屉外侧 20px、字段间隔 12px、整行点击区不低于 44px；高级参数只在选中相应方案时展开。

标志性元素是“提醒来源轨”：把`重要默认 → 强制 → 当前事项`或`普通默认 → 强制 → 单独改为重复`压缩成一行可读关系。它直接解释自动匹配与覆盖，不是装饰。

```text
事项编辑
┌──────────────────────────────────────┐
│ 事件类型  [普通 ▼]   [✓] 重要        │
│ 提醒方案  [强制 ▼]                    │
│ 来源      重要默认 ──▶ 强制           │
│            [为此事项单独设置]         │
└──────────────────────────────────────┘

已完成事项
┌──────────────────────────────────────┐
│ ✓ 完成季度预算核对                   │
│ 已完成于 2026-09-14 18:20            │
│                           [恢复为未完成] │
└──────────────────────────────────────┘

数据与小结
┌──────────────────────────────────────┐
│ 周期 [季度] [2026 年第三季度]         │
│ 模板  2026工作小结.docx  [检查模板]   │
│ 42 条 · 完成 31 · 逾期 3 · 重要 8    │
│ [查看占位符清单]          [生成 Word] │
└──────────────────────────────────────┘

仓库冲突
┌──────────────────────────────────────┐
│ 同一事项 · 2 个字段不同               │
│ 本机：重复提醒 17:00                  │
│ 仓库：强制提醒 18:00                  │
│ [保留本机] [保留仓库] [逐字段选择]    │
└──────────────────────────────────────┘
```

### 9.2 第二轮：产品原则复核与删减

- 不把七种默认方案做成七张彩色大卡；使用紧凑表格和来源文字，避免设置页像通用仪表盘。
- 不在事项卡片常态展示长继承链；只有编辑时显示来源，列表仍只显示最终提醒方案。
- 已完成列表沿用现有事项卡片和完成时间轨，只增加结果明确的`恢复为未完成`；不新增确认弹窗或第二套状态编辑器。
- 不在快速录入增加“重要默认”“模板”或“冲突”入口；复杂度留在后台。
- 不为 Word 生成加入封面预览动画、AI 文案框或在线模板市场；预览只呈现数据口径、占位符状态和保存位置。
- 不用红/绿决定仓库版本胜负；差异字段同时用文字和边框标明，键盘可逐项选择。
- 去掉“智能去重”这类含糊文案，明确区分“内容完全相同，自动合并”和“内容有差异，需要选择”。
- 重复详情通知开关不与持续通知、置顶窗并列成新的提醒渠道；它放在内容设置下，并明确“不改变提醒频率”。
- 动画不是必要信息；减少动态效果下来源轨和冲突切换均为静态。浅色、深色、高对比度均保留文字状态与可见焦点。

复核结论：后台各处分别只回答“默认怎么来”“是否恢复未完成”“小结写到哪里”“冲突保留哪份”，唯一新增视觉语言是有业务含义的来源轨；其余沿用现有 token，删除模板化统计卡和装饰。

## 10. 验收标准

### 10.1 提醒默认与重要标记

1. 普通默认改为强制后，既有普通事项不变；待选事项随后改为普通时，编辑器立即变为强制。
2. 用户把该事项单独改为重复并保存后，再次打开仍显示重复和“单独设置”。
3. 只修改标题、备注、类型、标签或时间不覆盖单独设置。
4. 开启重要标记时立即使用重要默认；关闭时恢复当前事件类型默认。
5. 更改默认值不批量修改既有事项；点击恢复默认才改变当前事项。
6. 保存失败时事件类型、重要状态、提醒方案和未来计划全部保持原样。
7. 休眠、重启、多开、系统时间回拨和方案切换不会补发历史提醒或制造重复提醒。

### 10.2 已完成事项恢复

1. 后台“已完成”筛选中的事项可执行`恢复为未完成`，恢复后进入未完成列表且稳定 ID 不变。
2. 标题、备注、类型、标签、事件类型、重要标记、截止时间和提醒方案保持不变，完成历史可审计。
3. 原截止时间已过时显示逾期，不静默顺延；一次性提醒已失效时不补发，并提示可调整时间。
4. 恢复只生成未来有效提醒，休眠、重启、时间回拨和多开均不补发完成期间的历史提醒。
5. 恢复事务失败时仍为已完成，不出现状态已开但计划未恢复的半成品。
6. 恢复修订经个人仓库同步后，其他设备不会把同一事项重复创建为新记录。

### 10.3 Word 小结

1. 用户能选择任意月或季度、有效 `.docx` 模板和保存位置，生成可重新打开的 Word 文档。
2. 单值占位符保留周边样式；明细模板行按事项数复制并保留行格式。
3. 月末、季度边界、年末、闰日和时区变化的统计范围正确。
4. 未知占位符、损坏模板、只读目录和磁盘写入失败均不改变模板或事项，不留下损坏输出。
5. 文档不包含回收站事项、凭据、路径、内部 ID、诊断信息或未请求的数据。
6. Windows Word/WPS、macOS Word/Pages、Linux LibreOffice 至少各记录一次兼容结果和已知降级。

### 10.4 仓库去重

1. 同一数据包重复同步不会新增事项或冲突。
2. 内容完全相同的历史冲突只保留一条默认可见事项，重复提醒停止，来源仍可追溯。
3. 标题相同但其他业务字段不同的两条事项不会自动合并。
4. 用户解决一对冲突并成功写入仓库后，另一设备同步不会重建同一对冲突。
5. 解决事务或快照写入失败可安全重试，不丢本机内容、不破坏原仓库包。
6. 清理前备份可验证；未知或损坏数据停止处理并给出恢复入口。

### 10.5 重复详情通知

1. 开关关闭时，重复通知与 v0.13.2 内容一致。
2. 开关开启时，重复通知负载包含可用的事件类型、类型、标签、到期、本次时点和下一次计划；空字段不显示。
3. 强调、一次性、强制和自定义方案的通知内容不变。
4. 开关变化不改变提醒频率、渠道、邮件策略、待确认状态或幂等键。
5. 详情生成失败仍发送原有简洁通知；系统截断时点击可打开完整事项。

## 11. 必测范围

- Rust 领域测试：默认优先级、重要开关、类型切换、单项覆盖、恢复默认、完成状态恢复、逾期/失效一次性恢复、旧数据迁移、未来计划重算、时间回拨和幂等。
- 数据层测试：schema v11→v12、迁移失败恢复、状态恢复事务回滚、完全重复判断、冲突解决传播、快照失败重试、损坏数据包。
- Word 测试：标量替换、表格行复制、中文与特殊字符、空集合、未知占位符、损坏模板、只读/磁盘失败、生成文件重新打开。
- UI 测试：事件类型切换即时匹配、重要优先级、手动覆盖、恢复默认、已完成事项恢复及失败回滚、模板校验、冲突键盘操作、成功/空/加载/失败/恢复文案。
- 通知测试：重复详情开关开/关、其他方案不变、长标题/多标签、锁屏隐私、平台截断降级。
- 视觉检查：真实中文内容、窄窗口、键盘焦点、中文输入法组合态、减少动态效果、浅色/深色/高对比度。

## 12. 待确认的产品取舍

本草案采用以下默认理解，用户确认整版 PRD 即视为同时确认这些取舍：

1. 版本按用户要求保持 v0.13.2；实现后重新生成同版本安装包、校验文件、变更说明和验收记录，不复用旧 v0.13.2 产物。
2. “重要”的默认方案优先于事件类型默认；用户单独设置仍然优先于两者。
3. “显示全面的通知”解释为“重复系统通知显示完整事项信息”，不是全屏弹窗；默认关闭，备注全文不进入系统通知。
4. 仓库只自动合并内容完全一致且来源可追溯的副本；有差异时必须由用户选择。
5. 月度/季度小结首版为离线、确定性 Word 生成，不使用云端 AI 写作；收到模板后再确认逐页占位符位置和最终兼容范围。
