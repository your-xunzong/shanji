# v0.12.0 自动更新与字体可读性 PRD 草案

> 状态：待用户确认；2026-09-08。确认前不修改功能代码、版本号、依赖或发布流程。

## 1. 目标

1. 用户主动允许后，闪记能从官方 GitHub Releases 检查新版本；发现正式发布的新版本时说明变化，由用户决定何时下载、安装和重启。
2. 更新前和更新后都提供简短、面向使用者的中文说明，不直接展示提交记录、内部模块名或技术错误。
3. 全面提高界面字体的清晰度和字号，统一中英文字形；不牺牲快速录入、窄窗口、甘特图密度和键盘可用性。

## 2. 自动更新范围

### 2.1 用户授权与检查时机

- 新增“自动检查更新”设置，默认关闭。v0.12.0 首次进入主界面时显示一次不阻塞的授权提示：“允许闪记每天连接 GitHub 检查新版本”；只有用户点击“启用自动检查”后才联网。
- 设置页“关于闪记”增加“立即检查更新”。用户点击即代表本次联网授权，即使自动检查关闭也可执行。
- 自动检查在应用后台启动 30 秒后进行；同一设备最多每 24 小时检查一次。休眠恢复后只有距上次成功或失败检查满 24 小时才再次检查，不使用高频轮询。
- 检查、下载和安装不得进入快速录入保存链路，不得延迟事项落盘、窗口隐藏或提醒调度。

### 2.2 哪些 GitHub Release 会被发现

- 固定更新来源为 `https://github.com/your-xunzong/shanji/releases/latest/download/latest.json`，不允许界面任意更换服务器。
- 只识别语义版本高于当前版本、已经正式发布且标记为最新稳定版的 Release。草稿和预发布不会推送给普通用户。
- 每个可更新 Release 必须同时包含：`latest.json`、当前平台的更新包、对应更新签名，以及供用户手动下载的正常安装包。缺失任一必需项时不向用户宣称可安装。
- 当前 GitHub 流程仍生成草稿预发布。实施时新增或调整正式发布链路：构建三平台产物和更新签名，生成 `latest.json`，先保持草稿；维护者在 GitHub 确认并发布为稳定 Release 后，客户端才会从 `/releases/latest/` 发现它。

### 2.3 发现、下载和安装体验

- 自动检查没有更新或暂时联网失败时保持安静，不抢焦点、不弹错误窗；设置页记录“上次检查时间”和简短状态。
- 发现更新后，主界面显示一条非模态提示，托盘菜单显示“新版本 vX.Y.Z”。若系统通知已启用，每个版本最多发送一次“新版本可用”标准通知；快速录入窗和提醒置顶窗不被覆盖。
- 用户打开更新详情后看到：当前版本、新版本、发布日期、3–6 条中文更新摘要和平台说明。提供“下载更新”“稍后提醒”和“打开发布页面”，不自动下载。
- 下载时显示真实字节进度和“取消下载”；完成后按钮变为“安装并重启”。安装前明确说明应用将重启，未保存的设置或编辑应先保存。
- 更新安装成功并首次重新打开主界面时，显示一次“已更新到 vX.Y.Z”，复用该版本随应用打包的中文用户说明。用户关闭后不重复出现；“关于闪记”仍可再次查看当前版本说明。
- “稍后提醒”只延后当前版本 24 小时，不改变自动检查设置。暂不提供永久跳过版本，避免遗漏安全修复。

### 2.4 更新说明来源

- 每个版本新增一份随源码管理的中文用户说明，内容只包含用户能观察到的变化、必要迁移和已知降级；构建检查要求版本号一致、正文非空且不超过 6 条。
- GitHub Release 正文和 `latest.json.notes` 使用同一份用户说明，应用内不抓取或渲染 GitHub 网页 HTML。
- 应用内仅展示纯文本和受控列表；链接只允许指向本仓库的 HTTPS Release 页面，避免远程富文本和脚本内容进入界面。

### 2.5 安全、隐私与数据

- 使用 Tauri 官方 updater 插件的签名校验。更新公钥随应用发布；私钥及密码只保存在维护者安全存储和 GitHub Actions Secrets，绝不写入源码、日志、SQLite 或 Release 附件。
- 签名不通过、版本清单损坏、URL 不属于允许的 GitHub 仓库或下载中断时，拒绝安装并保留当前版本。提示“更新无法验证，当前版本和本机数据未改变”，可重试或打开发布页手动下载。
- 更新请求不包含事项正文、备注、分类、标签、路径、SMTP 信息或设备标识。GitHub 仍会像普通 HTTPS 请求一样看到网络地址、请求时间、当前平台和客户端版本；授权提示中应说明这一点。
- 新增版本化迁移保存：是否自动检查、上次检查时间、当前版本稍后提醒时间、已提示版本和已读更新说明版本。迁移前沿用现有一致性备份；失败时保持旧数据库和旧应用可运行。
- 安装更新不得删除或移动事项数据库。新版本启动后仍先执行既有数据连续性检查和迁移备份，再进入正常界面。

### 2.6 平台差异

- Windows NSIS 安装版：支持在应用内下载签名更新包、运行被动安装并重启；Windows 发布者代码签名仍是独立门槛，未签名安装器可能继续触发系统安全提示。
- macOS 应用包：生成签名更新归档；正式启用安装前仍需实机验证应用签名、公证、权限和重启恢复。
- Linux AppImage：支持签名更新包并实机验证替换；`.deb` 安装及包管理器场景只提示新版本并打开 Release 页面，不擅自覆盖系统包。
- Windows 便携版：首版只检查、显示说明并打开便携包下载页，不自动替换正在运行的程序，也不改动便携数据目录。
- 第一个包含更新公钥的 v0.12.0 必须由用户手动安装；使用 v0.12.0 检测并安装 v0.12.1，才是完整更新验收。

## 3. 字体与字号范围

### 3.1 字体系统

- 中文界面字体改为平台原生优先：Windows 使用 `Microsoft YaHei UI`，macOS 使用 `PingFang SC`，Linux 优先 `Noto Sans CJK SC`，再回退到 `system-ui` 和无衬线字体。
- 中文标题不再使用只适合拉丁字符的 `Bahnschrift` 作为首选，避免中英文混排时字形、字重和基线不一致。
- 时间、版本号和进度数字保留等宽字体：`Cascadia Mono`、`SFMono-Regular`、`Noto Sans Mono` 及系统等宽回退。
- 不下载远程字体，不增加字体文件、联网请求或安装包体积；尊重操作系统 DPI 与文字缩放。

### 3.2 字号基线

- 页面正文默认 `14px / 1.55`；按钮、输入框和主要标签不小于 `13px`；说明、元数据、日期刻度和状态文字不小于 `12px`。
- 页面主标题为 `26–30px`，面板标题 `22–24px`，卡片/小节标题 `14–16px`；快速录入正文输入维持高辨识度，不因后台密度调整而缩小。
- 删除当前大量 `8–10px` 的用户可见文字。不得用整体缩放 CSS 粗暴放大；逐一调整导航、事项卡、设置、提醒中心、邮件、仓库、恢复页和甘特图，避免按钮截断和布局溢出。
- `760×560` 主窗口、`660×316` 与 `520×300` 快速录入窗口仍须完整显示核心操作；必要时减少装饰间距或让后台抽屉滚动，不缩回小字号。

## 4. 页面设计方向

- 主界面发现更新时只增加一条紧凑提示，不使用强制居中的营销弹窗；更新详情使用现有右侧抽屉，不遮挡快速录入。
- 标志性元素为“版本轨”：当前版本和新版本分别是时间轨上的两个节点，下载进度沿轨道推进，表达从当前安全版本到已验证新版本的真实状态。
- 更新说明使用短句列表，第一条先讲最重要的用户变化。没有“全新体验”“重磅升级”等空泛文案。
- 浅色、深色、高对比度和强制颜色模式均用文字、节点形状和进度数值表达状态；减少动态效果时进度只更新数值和长度，不播放脉冲或庆祝动画。

## 5. 失败与恢复

- 手动检查失败：显示“暂时无法检查更新；事项和当前版本未受影响”，提供“重新检查”和“打开发布页”。技术详情去敏并默认收起。
- 自动检查失败：不弹窗；只在设置页显示状态，下次不早于 24 小时再试。
- 下载取消或中断：删除未完成临时包，不更改当前程序；再次下载从插件支持的安全起点重新开始，不伪造续传。
- 签名失败：绝不提供“仍然安装”；只允许重新检查或打开官方发布页。
- 安装失败：当前数据不变，说明是否需要手动下载安装包；不得循环重启。
- 更新后数据迁移失败：沿用启动数据保护页，保留迁移前备份，不进入空事项列表。

## 6. 非目标

- 不做静默强制安装、后台自动下载、增量更新、版本回滚、灰度发布、预发布频道或自建更新服务器。
- 不让 GitHub Release 内容远程控制应用 UI，不执行远程脚本或 HTML。
- 不在本版完成 Windows 商店、macOS App Store、Linux 软件源更新，也不把代码签名/公证误写成已经完成。
- 不增加账号、遥测、事项同步或任何事项内容上传。
- 不提供自定义字体、任意字号滑块或主题重做；本版只建立更清晰的一套默认字体与字号。

## 7. 验收标准

1. 未授权自动检查时，启动和使用 24 小时均不访问更新地址；点击“立即检查”只访问固定 GitHub Release 更新端点。
2. 自动检查开启后，同设备 24 小时内只检查一次；启动、休眠恢复和系统时间回拨不制造检查风暴，也不影响快速保存 P95。
3. 发布含完整签名资产的稳定 v0.12.1 后，v0.12.0 能发现它，显示版本、发布日期和同源中文说明；草稿、预发布、同版本、低版本和资产不完整的 Release 均不提示安装。
4. 篡改 `latest.json`、更新包或签名时安装被拒绝，当前应用和事项数据库保持可用；日志不含事项内容或私钥。
5. Windows NSIS 完成下载、安装、重启后只显示一次“已更新到 v0.12.1”，可在关于页再次查看说明；稍后提醒、取消下载和断网重试均有明确结果。
6. Windows 便携版、Linux `.deb` 只提示和打开正确下载页；macOS、Linux AppImage 未完成实机验证前明确标注降级，不宣称自动安装完成。
7. 全部用户可见常规文字在 100% 缩放下不小于 12px；中英文混排无明显基线跳动，主窗口与快速录入最小尺寸无截断或遮挡。
8. 使用真实中文事项检查浅色、深色、高对比度、强制颜色、减少动态效果、键盘焦点、IME 组合态以及更新成功、无更新、检查失败、下载中、签名失败、安装失败和更新后恢复路径。

## 8. 实施前置条件

- 用户确认本草案后，先同步 `docs/PRD.md`，并新增 ADR 记录 GitHub 静态更新清单、Tauri updater、密钥生命周期和各平台降级。
- 需要生成一对长期使用的更新签名密钥：公钥提交到配置；私钥由维护者保存并写入 GitHub Actions Secrets。私钥丢失将导致已安装客户端无法验证未来更新，因此生成和备份必须由用户明确授权。
- 当前 Releases 页面可作为唯一官方来源，但首个端到端测试必须使用两个版本：手动安装 v0.12.0，再从正式发布的 v0.12.1 更新。
