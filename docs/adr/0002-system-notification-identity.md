# ADR 0002：系统通知身份与平台适配器

- 状态：已接受
- 日期：2026-08-28
- 对应版本：0.1.1

## 背景

现有提醒调度能生成数据库事件，但 Windows 便携版缺少可靠的应用通知身份；同时插件的异步发送路径不能证明操作系统已接受通知，导致 `QUEUED` 被误解为用户已经看到横幅。

## 决策

1. 领域调度只负责原子领取提醒，不直接依赖平台通知库。
2. 新增通知平台适配器，返回明确的提交成功或失败结果；数据层据此把事件更新为 `SUBMITTED` 或 `FAILED`。
3. Windows 安装版使用稳定的 AppUserModelID `com.shanji.desktop`；便携版使用独立的 `com.shanji.desktop.portable`，避免便携版撤销注册时破坏安装版身份。
4. 安装版启动时校验并补齐安装器对应的当前用户通知身份。便携版仅在用户明确授权后，在当前用户范围注册显示名称和图标；不使用 PowerShell 作为通知来源。
5. 便携注册必须可撤销，只清理由闪记创建的键值。普通程序数据和便携数据库不与系统身份混放。
6. 点击 Windows 通知时，通过线程安全的应用句柄请求主线程显示并聚焦主窗口。
7. macOS/Linux 继续通过 Tauri 通知适配器，并分别处理权限拒绝与通知服务缺失。

## 影响

- Windows 增加小型、目标平台限定的 WinRT 与当前用户注册表依赖，不引入常驻服务或网络能力。
- 便携模式在启用原生通知后不再是完全零系统痕迹，因此必须明确告知并提供撤销。
- 操作系统接受通知仍不保证横幅可见；系统专注模式属于外部状态，界面必须准确表述。
