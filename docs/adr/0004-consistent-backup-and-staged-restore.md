# ADR 0004：使用 SQLite 一致快照与重启边界恢复数据

- 状态：已接受
- 日期：2026-08-28
- 适用版本：v0.3.1 起

## 背景

安装版、便携版和 SQLite WAL 使“复制一个 `shanji.db` 文件”不足以保证包含最近提交的数据。数据库正在使用时直接覆盖文件还可能产生损坏或混合版本。

## 决策

1. 安装版始终使用系统应用数据目录；只有程序目录存在 `portable.flag` 时才使用同目录 `data/shanji.db`。
2. 手动备份和 schema 升级前备份均通过 SQLite `VACUUM INTO` 生成一致快照，并记录 schema 版本、事项数量和更新时间。
3. 恢复分为两个阶段：运行中的应用先验证候选数据库、备份当前库并生成一致的待恢复快照；应用重新启动、数据库尚未打开时再原子移动当前库并启用快照。
4. 被替换的当前库改名保留为 `shanji-before-restore-*.db`，不会直接删除；恢复失败时当前数据保持不变。
5. 只允许恢复应用识别出的候选文件，并拒绝空库、完整性检查失败或 schema 高于当前应用的数据。

## 影响

- 优点：覆盖安装、WAL、迁移失败和恢复中断都有明确恢复点；无需引入后台服务或网络依赖。
- 代价：备份需要与数据库大小相当的额外磁盘空间；大型数据库备份时间增加，但不位于快速录入保存路径。
- Windows/macOS/Linux 使用相同 SQLite 机制。打开数据目录分别调用系统文件管理器；调用失败时仍显示可复制的数据路径。
