# ADR 0006：可组合提醒渠道与安全 SMTP

- 状态：已接受
- 日期：2026-08-29
- 适用版本：v0.5.0 起

## 背景

操作系统横幅可能被专注模式、通知设置或桌面环境抑制，单一通知方式无法证明用户已经看到提醒。与此同时，邮件属于会把事项内容发送到本机之外的网络渠道，必须保持默认离线、明确授权和可追溯失败语义。

## 决策

1. 标准系统通知、原生持续提醒、应用置顶提醒窗、未确认重复提醒和待确认提醒中心保持独立开关与测试入口。关闭或失败一种方式不阻塞其他方式。
2. Windows 的“今日必做”优先使用原生 `Reminder` 场景和操作按钮；平台拒绝时降级为标准通知并记录降级原因。macOS/Linux 继续使用标准通知，并把应用置顶窗作为可选的确定性补充。
3. 待确认提醒中心和托盘数量从 SQLite 事实状态查询。打开窗口或关闭横幅不视为确认；只有完成、暂停、稍后提醒或明确“确认已看到”改变当前提醒状态。
4. 应用置顶窗使用独立 Tauri 窗口，默认关闭，不主动请求焦点；同一提醒事件用稳定渠道幂等键只记录一次，多个提醒在前端排队处理。
5. SMTP 采用 `lettre` 的 TLS/STARTTLS 同步传输，并只在后台调度线程或用户主动测试时运行。快速录入和本地保存路径不等待网络。
6. SMTP 密码使用 `keyring` 写入 Windows Credential Manager、macOS Keychain 或 Linux 的本机安全凭据后端；SQLite 只保存非敏感连接参数，日志和导出均不包含密码。
7. 邮件只对用户启用的标签路由生效，默认每个事项首次到期发送一次。“今日必做每次重复发邮件”需用户单独开启。每次投递原子领取，失败后在 1 分钟、5 分钟最多重试两次，总尝试次数不超过 3 次。

## 影响

- 优点：用户可组合“系统可见性”和“应用内确定性”；即使未看到横幅，也能在提醒中心追回事项；网络渠道不会破坏离线保存主链路。
- 代价：新增 TLS 与系统凭据依赖，安装包和首次构建体积增加；SMTP 成功只表示服务器接受邮件，无法保证收件箱最终展示。
- Windows：支持原生持续提醒操作、Credential Manager 和置顶提醒窗；专注助手仍可能抑制系统横幅。
- macOS：使用 Keychain；通知持续样式由系统设置决定，置顶窗与邮件可作为补充，需真实设备验证权限和焦点行为。
- Linux：使用本机 Secret Service/keyutils 组合后端；无可用凭据服务时邮件设置明确失败且不回退到明文文件。桌面通知持续性和托盘事件按环境降级。

## 依赖审查

- `lettre 0.11.23`：MIT，Rust 1.74+，启用 builder、SMTP、Rustls 与平台证书验证相关最小功能，不引入异步运行时。
- `keyring 3.6.3`：MIT/Apache-2.0，兼容项目 Rust 1.85；启用三平台原生/持久凭据后端。v4 需要更高 Rust 版本，当前不采用。
