# ADR-0010：本地运行库与个人仓库数据包分离

- 状态：已接受
- 日期：2026-09-03
- 关联版本：v0.8.0

## 背景

用户可能在安装版、便携版、同步目录和多台电脑之间留下多份数据。直接把正在写入的 SQLite 放到同步盘、网络盘或可移除介质，会把文件锁、断开和半同步风险带入快速保存路径；按文件更新时间选择“最新库”也无法判断两边是否都有修改。

## 决策

1. 应用继续只在系统应用数据目录或显式便携目录打开运行库。个人仓库只保存版本化数据包，不直接承载运行中的 SQLite。
2. 数据包包含稳定实例 ID、包版本、导出时间、schema、受支持业务表的快照和 SHA-256 校验；不包含仓库绝对路径、系统凭据、临时迁移文件或平台专属开机启动状态。
3. 写数据包使用“临时文件—刷新—校验—原子替换”。读取时先校验格式、版本、摘要和表白名单；未知表、未知包版本或校验失败时停止归并。
4. 归并以事项 ID、revision、删除墓碑和已见修订为依据。已见记录同时保存来源修订、内容摘要和本机目标事项 ID；相同数据包再次归并时复用仍存在的目标，不重复创建冲突副本。相同修订幂等跳过；只在一侧变化时接受新修订；无法证明单边变化时创建完整冲突副本，不逐字段拼接。
5. 归并前创建一致性备份，事项、标签关系、提醒历史和删除记录在一个事务中导入。失败时回滚运行库，原数据包保持不变。
6. 仓库不可用时本机继续保存与提醒，只持久化“等待归并”状态并采用用户操作或低频启动检查重试，不新增高频轮询。

## 影响

- `sha2` 与 `hex` 作为直接依赖用于数据包完整性校验；两者为小型纯 Rust、MIT/Apache-2.0 生态依赖，已被现有依赖树间接使用，不新增运行时服务、权限或联网。
- 数据包是跨平台 JSON，不保存平台路径；正文属于用户主动选择写入个人仓库的数据内容，但不会进入日志或诊断。
- 首版采用保守冲突策略，可能比“最后写入覆盖”产生更多冲突副本，但不会静默丢失完整版本。

## 被否决的方案

### 直接从同步盘打开 SQLite

不同同步工具无法保证 SQLite 数据库、WAL 和 SHM 的锁与原子顺序，断开时还会阻塞快速保存。

### 按标题或更新时间自动去重

标题不是稳定标识，设备时钟也可能漂移；二者都不足以授权覆盖用户内容。
