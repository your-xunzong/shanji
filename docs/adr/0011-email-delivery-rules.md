# ADR-0011：邮件规则与提醒计划、通知渠道分层

- 状态：已接受
- 日期：2026-09-03
- 关联版本：v0.9.0

## 背景

v0.5.0 只提供标签路由和“今日必做是否每次发送”的全局开关，无法表达事件类型、单选类型、首次到期、每日首次、每个计划时点和每日摘要。继续增加全局布尔字段会把时间规则、匹配条件和渠道混在一起。

## 决策

1. 新增独立邮件投递规则：匹配维度为事件类型、单选类型或标签；投递策略为首次到期、每天第一次、每个计划时点或每日摘要；每条规则明确收件地址、启用状态和摘要时间。
2. 事项提醒计划仍决定何时产生提醒事件。邮件规则只决定该事件是否进入邮件渠道，不修改事项到期时间、事件类型或本机通知。
3. 同一提醒事件命中同一地址的多条规则时使用稳定幂等键只创建一条投递；首次和每日首次按事项/当地日期建立独立唯一键。
4. 每日摘要先写入持久队列，到规则的当地摘要时间后按地址合并；断网和认证失败使用已有有限重试，不阻塞本地保存。
5. v0.5.0 已启用标签迁移为“首次到期”规则；旧高频开关只用于迁移今日必做策略，之后由规则事实状态接管。
6. 邮件同时提供纯文本与内联样式 HTML。不得加载远程图片、字体或跟踪像素；日志只记录错误类别和投递 ID，不记录标题、正文、地址或凭据。

## 影响

- Windows、macOS、Linux 共用规则、队列和幂等逻辑；凭据继续只进入系统安全存储。
- SMTP 服务器接受只表示已提交，不表示用户已阅读；界面和历史不得使用“已读”“送达用户”等表述。
- 删除或禁用规则停止未来入队，既有终态历史保留；待发送任务转为 `DISABLED`，不无限重试。

## 被否决的方案

### 把邮件做成新的提醒方案

渠道变化不应改变时间；这种建模会使切换邮箱意外重算提醒。

### 在快速保存时直接发送

网络等待会破坏一次提交和可靠落盘，SMTP 失败也不应撤销本地事项。
